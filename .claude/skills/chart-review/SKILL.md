# チャートの AI 確認

機械的な変換（gherkin2puml）は文の形しか見ない。図が仕様どおりか・人が読めるかは、画像で見て確認する。
**合否は決めない**（合否は feature のテストだけ）。指摘するだけ。

## 手順

1. `make docker-chart` で `charts/**/*.png` を最新にする（対象 feature のものだけ見ればよい）
2. 対象の `docs/specs/<名前>.md` と `tests/features/<名前>.feature` を読む
3. PNG を Read で 1 枚ずつ開いて見る。次を確認する
   - **仕様との一致**: 入力の変化時刻・値、出力の期待値が、仕様書の表としきい値どおりか（境界値の両側が出ているか）
   - **意図が読めるか**: 何を確認する図か、タイトルとメモだけで分かるか
   - **見にくさ**: 信号名・値の文字切れや重なり、時間軸が詰まりすぎ／間延び、確認時点の印が見えない、信号の並び順が不自然、単位の抜け
4. 結果を図ごとに報告する: 問題なし / 指摘（何が・どう見えるか・直し方の案）
5. 直す場所を切り分けて提案する
   - 図の見え方 → `tools/gherkin2puml.py`
   - シナリオの組み立て → feature（`/spec-to-gherkin`）
   - 仕様との食い違い → 仕様書か feature のどちらが正しいかをユーザーに確認する（勝手に直さない）
6. 直したら `make docker-chart` で再生成し、`.puml` / `.svg` / `.png` を feature と一緒にコミットする

## 図の読み方（gherkin2puml の描き方）

- 入力は波形（数値）か帯（ON/OFF・値が変わらないもの）。出力は常に文字の帯で、確認する前は「?」
- 黄色の「確認」の帯は、期待値を確認する時点から始まる。帯の中で期待値が始まっていればよい
- 時間軸の右側が空白なのは、PlantUML が軸を最後の時刻の約 2 倍まで伸ばすため（不具合ではない）
- 時刻が近い確認が重なると「確認」の文字が重なる。値と時刻が読めれば許容する

## 注意

- 同じ形の図（`Scenario Outline` の Examples 由来）が多いときは、境界値と異常系を優先して見る
- 見えたものだけを報告する。読み取れない部分は「読み取れない」と書く
