# チャートの AI 確認

機械的な変換（gherkin2puml）は文の形しか見ない。図が仕様どおりか・人が読めるかは、表で突き合わせて確認する。
**合否は決めない**（合否は feature のテストだけ）。指摘するだけ。

## 手順

1. `make docker-chart` で `charts/` を最新にする
2. 対象の `docs/specs/<名前>.md`、`tests/features/<名前>.feature`、`charts/<名前>/*.puml` を読む
3. **仕様の項目を洗い出す**: 仕様書のパラメータ表と振る舞いの文から、確認すべき項目を行にして書き出す
   - 各しきい値の境界の両側（「以上」「超え」の違いを含む）、時間条件（N ms 未満 / ちょうど）、復帰・解除、異常時
4. **項目ごとに feature と図を探して突き合わせる**。次の表を作る

   | 仕様の項目 | シナリオ（feature） | 図（.puml で値と時刻を確認） | 判定 |
   |---|---|---|---|

   判定は ○（一致）/ ×（食い違い）/ 漏れ（対応するシナリオがない）。次を 1 項目ずつ見る
   - **値と単位**: 入力・期待値が仕様書の表の値と同じか。数値を feature が勝手に作っていないか
   - **時刻**: `.puml` の `@t` と確認の位置が、feature の「N ms 経過する」の合計と合っているか
   - **期待値**: 確認する出力の値が、仕様の振る舞いから導かれる値と合っているか（ON/OFF の取り違えなど）
   - **漏れ**: 仕様書にあるのに、どのシナリオにも出てこない行
5. **PNG を Read で開いて、図として読めるか見る**（`.puml` で足りる値の確認とは別に）
   - 信号名や値の文字切れ・重なり、時間軸、確認の帯が見えるか、信号の並び順
   - `Scenario Outline` の同形の図は、境界値と異常系を優先して開く。`.puml` はすべて読む
6. 結果を機能ごとに、上の表と「見にくさの指摘」で報告する。×・漏れは、直す場所を切り分けて提案する
   - 図の見え方 → `tools/gherkin2puml.py`
   - シナリオの組み立て・漏れ → feature（`/spec-to-gherkin`）
   - 仕様と feature の食い違い → どちらが正しいかをユーザーに確認する（勝手に直さない）
7. 直したら `make docker-chart` で再生成し、`charts/` を feature と一緒にコミットする

## 図の読み方（gherkin2puml の描き方）

- 入力は波形（数値）か帯（ON/OFF・値が変わらないもの）。出力は常に文字の帯で、確認する前は「?」
- 黄色の「確認」の帯は、期待値を確認する時点から始まる。帯の中で期待値が始まっていればよい
- 時間軸の右側が空白なのは、PlantUML が軸を最後の時刻の約 2 倍まで伸ばすため（不具合ではない）
- 時刻が近い確認が重なると「確認」の文字が重なる。値と時刻が読めれば許容する

## 注意

- 見えたものだけを報告する。読み取れない部分は「読み取れない」と書く
- 表の ○ は、実際に値を照らしたものにだけ付ける
